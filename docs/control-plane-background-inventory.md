# Shared-server background execution inventory

This inventory describes the checkout after phase 46. It identifies persistence,
entry-point families, execution boundaries and remaining work. It does not certify
that the composite background stage is complete. Installed plugin code is trusted
operator code; workflow bodies and automation prompts/scripts are tenant input.
A plugin name, origin field or parent thread ID is never a user credential.

| Generic background service              | Plugin runtime registration and in-memory supervised task/AbortController                                              | Trusted service identity, restart/backoff and quiesce state. Central and plugin SQLite stores are separate. Reservation and native persistence
are not a distributed transaction. An incomplete reserved source can exist;
phase-44 personal reads omit it while advancing the cursor, and direct reads
return 404. Recovery must preserve authority evidence rather than invent an owner.
Browser session tokens are not durable background authority.

The launcher uses numeric UID/GID, cleared supplementary groups, no-new-privileges
and per-job namespaces. It is not a filesystem jail or a network boundary.
Different jobs of the same user share that user's HOME and filesystem privileges.
A script runtime must state those limits instead of promising project-directory
confinement merely because it sets cwd.

## Script launcher work that follows this inventory

The first supported script mode must have a fixed operator-installed interpreter
and launcher entry point, with source/arguments passed as bounded input after
identity is selected. Reject unsupported interpreters, host cwd overrides and
service environment injection. No user-supplied command may run in the BB service
as a fallback when the managed runtime is unavailable.

Reuse native automation definitions, immutable versions, schedule claims and run
history. Bind saved owner/project/origin/profile authority before executing, and
recheck it at actual launch and after restart. Persist the process/lease identity
and cancellation intent; a script process must not be disguised as a Qwen thread.
Start acknowledgement, terminal result and confirmed descendant cleanup are
separate states. Do not auto-replay a running script after a crash under an
exactly-once claim.

Output/error/status must be bounded and owner-scoped. Pause/delete/revoke must
fence pending starts and stop active descendants; stopping one run must preserve
other owners and unrelated runs of the same owner. Restore pending cleanup after
restart. Extend the limited domain/SDK/CLI/UI contract explicitly when script mode
is available; until then personal create/edit remain agent-only.

Required runtime acceptance includes two real numeric UIDs, HOME/cwd proofs,
foreign filesystem/process/credential denial, cancellation during attachment and
execution, grant loss, lost acknowledgements and abrupt crash recovery. Existing
workflow/agent tests do not substitute for this new runtime's tests.

## Verification boundary

Phase 47 reruns the existing real-SQLite security contracts for background jobs,
thread ownership, workflow workers, send-commit rechecks and Automations, plus the
full normal Docker deployment. This checks that the mapped existing boundaries
still work. It does not add script execution, prove arbitrary machine RPC safe or
close the queue/retry/notification audit. Phase 46's browser proof remains the UI
baseline; this documentation increment does not rerun browser acceptance.
